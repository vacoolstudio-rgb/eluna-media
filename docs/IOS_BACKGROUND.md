# Фон на iOS: пауза вместо вранья

Дата: 2026-08-16. Проект интерфейса и реализации. Ничего из описанного здесь
пока не написано — документ существует, чтобы решение принималось до кода, а не
после.

**Задача.** На Android конвертация переживает сворачивание: держит
foreground-сервис, показывает прогресс в уведомлении, доводит батч до конца. На
iOS этого нет и не будет. Сейчас приложение об этом молчит — а молчание здесь
читается как обещание, которого система не даст.

---

## 1. Что iOS даёт на самом деле

| Механизм | Что даёт | Годится ли для конвертации |
|---|---|---|
| Ничего не делать | Приложение засыпает через несколько секунд после сворачивания | Нет: FFmpeg замирает на середине кадра, а очередь считает, что работа идёт |
| `beginBackgroundTask` | Разово ~30 секунд (система не обещает точной цифры) на «доделать начатое» | Только чтобы **дожать почти готовое** |
| `BGProcessingTask` | Долгие задачи, но **система сама решает когда** — ночью, на зарядке, при простое | Нет: пользователь ждёт файл сейчас, а не «когда-нибудь» |
| Аудиофон, VoIP, локация | Полноценный фон | Нет: у нас нет для этого честного основания, и Apple отклоняет за такие «фоновые режимы для галочки» |

**Вывод: полноценной фоновой конвертации на iOS быть не может.** Значит, единственная
честная механика — **пауза с внятным объяснением**.

Отдельно: у FFmpeg **нет паузы**. Сессию можно только отменить. Поэтому
«поставить на паузу» на уровне продукта означает два разных действия на уровне
кода, и путать их нельзя:

- **очередь** ставится на паузу по-настоящему — следующий файл просто не
  запускается;
- **текущий файл** либо успевает добежать в подаренные системой секунды, либо
  отменяется и при возвращении **начинается заново**.

Второе надо сказать пользователю словами. Скрытая потеря пяти минут работы —
это ровно тот класс тихо неправильного поведения, из-за которого в проекте
живут `StillDecoder` и тест на плиточный HEIC.

## 2. Поведение

### При сворачивании (`applicationDidEnterBackground`)

1. Берём `beginBackgroundTask` — окно на доработку.
2. **Очередь замирает**: файл, который ещё не начинали, не начинаем.
3. Текущий файл продолжает считаться, пока окно не кончится.
4. Если он успел — задание закрывается как обычно, а очередь остаётся на паузе.
5. Если не успел — сессия отменяется, частичный выход удаляется (уже так и
   делается при отмене), задание возвращается в состояние «в очереди» с
   пометкой «прервано системой», прогресс обнуляется.
6. `endBackgroundTask`.

### При возвращении (`applicationWillEnterForeground`)

- Если что-то было прервано — **не возобновляем молча**. Показываем состояние
  паузы и кнопку «Продолжить»: человек ушёл из приложения намеренно и мог
  передумать, а гигабайтный ролик начнёт греть телефон без спроса.
- Исключение: если ничего не прерывалось (батч успел закончиться), показываем
  обычный результат.

### Пока конвертация идёт на переднем плане

`UIApplication.shared.isIdleTimerDisabled = true` — экран не гаснет. Это не
украшение: гаснущий экран на iOS ведёт к тому же сворачиванию, и без этого
пятиминутная конвертация обрывается у любого, кто отложил телефон. Флаг
снимается сразу по окончании батча (и в `deinit`, чтобы не залипнуть).

### Уведомление

Одно локальное уведомление в момент прерывания:
«Конвертация приостановлена. iOS останавливает работу свёрнутых приложений —
откройте Eluna Media, чтобы продолжить». Разрешение на уведомления у приложения
уже есть (им пользуется сообщение о готовности батча).

## 3. Интерфейс

### 3.1. Полоса состояния над очередью

Появляется только на iOS и только когда есть прерванное:

```
┌────────────────────────────────────────────────┐
│  ⏸  Приостановлено системой                    │
│     iOS останавливает свёрнутые приложения.    │
│     «Море.mov» начнётся заново.                │
│                            [ Продолжить ]      │
└────────────────────────────────────────────────┘
```

Третья строка появляется, **только если файл действительно придётся начать
заново**. Если прервать успели между файлами, её нет — врать про потерянный
прогресс так же плохо, как молчать о нём.

### 3.2. Карточка задания

Состояние «на паузе» — отдельное, не «идёт» с замершим процентом. Циферблат
показывает последний достигнутый процент серым, подпись: «Приостановлено».

### 3.3. Объяснение — один раз

При первом же прерывании — шторка (не алерт), с тремя строками и одной
кнопкой:

```
        Почему конвертация остановилась

  iOS не разрешает приложениям работать в фоне —
  это правило системы, а не выбор Eluna Media.
  На Android то же приложение доводит батч до конца.

  Чтобы конвертация не прерывалась:
  • не сворачивайте приложение и не блокируйте экран;
  • экран сам не погаснет, пока идёт конвертация.

                  [ Понятно ]
```

Показывается один раз за установку — как «что нового». Прямая ссылка на неё
остаётся в настройках.

### 3.4. Настройки

Строка в разделе конвертации, видна только на iOS:

> **Работа в фоне** — недоступна на iOS
> Система останавливает свёрнутые приложения. Очередь встаёт на паузу и ждёт
> возвращения.

### 3.5. Чего в интерфейсе быть не должно

- Прогресса, который не двигается, без слова «приостановлено».
- Слова «в фоне» в описаниях функций на iOS — включая магазин: строку про
  фоновую конвертацию надо разводить по платформам.
- Кнопки «продолжить в фоне» с пояснением «может не работать».

## 4. Что писать в коде

| Где | Что |
|---|---|
| `ios/Runner/AppDelegate.swift` | `beginBackgroundTask`/`endBackgroundTask` вокруг окна; канал `eluna/lifecycle` с событиями `willSuspend` (окно началось) и `didExpire` (окно кончилось) |
| `lib/services/foreground_service.dart` | На iOS перестаёт быть немой заглушкой: подписывается на эти события |
| `lib/state/queue_controller.dart` | Состояние `paused` у очереди; `interruptedBySystem` у задания; запрет старта следующего файла на паузе; отмена текущего по `didExpire` с возвратом в `queued` |
| `lib/services/screen_awake.dart` (новый) | `isIdleTimerDisabled` на время батча |
| `lib/ui/queue_tab.dart` | Полоса состояния, состояние карточки, кнопка «Продолжить» |
| `lib/ui/settings_tab.dart` | Строка про фон |
| `lib/l10n/*.arb` | Шесть новых строк × 61 язык |

**Тесты.** Хостовые: очередь на паузе не берёт следующий файл; прерванное
задание возвращается в `queued` с нулевым прогрессом; полоса появляется только
при наличии прерванного и упоминает файл только когда он и правда начнётся
заново. На устройстве: `isIdleTimerDisabled` действительно поднят во время
батча — единственное, что нельзя проверить на хосте.

---

## 5. Оценка

Полтора-два дня, из них половина — строки на 61 язык и тесты. Риск низкий:
ничего из этого не трогает сам конвейер конвертации, только то, когда очередь
имеет право начать следующий файл.

**Порядок:** сначала пауза и `isIdleTimerDisabled` (без них приложение теряет
работу молча), потом полоса и карточка, потом шторка и настройки, строки —
последними, когда формулировки перестанут меняться.
